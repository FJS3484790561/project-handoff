# 轻量头脑风暴

基于 Superpowers brainstorming 改编，保留需求对齐，移除后续技能调用和强制子代理审查。来源与许可见 [来源说明](references/upstream.md)。

## 对齐需求

先阅读已有项目说明和用户提供的上下文，沿用已经确认的决定。需求清楚的小修改直接按普通开发处理，不重新访谈。

需要澄清时，一次围绕一个关键问题展开，优先让用户描述具体使用场景。用户已说明的内容不要重复问。覆盖这些信息即可，不逐项机械提问：

- 谁在什么场景使用，最重要的目标是什么。
- 本期做什么、不做什么，怎样算完成。
- 已有条件、必须遵守的约束，以及用户有偏好的技术选择。
- 有实质取舍时比较两三个可行方案，并给出推荐理由。

用户让你自行决定的事项，采用简单合理的默认值并注明；不要把自己的建议写成用户已确认的决定。用户要求停止问答时，用现有信息继续。

## 输出

对新项目写入 `docs/product.md`；已有项目优先更新其权威需求文档，不复制一套互相冲突的规格。包括目标、用户与场景、本期范围、不做事项、约束、验收条件和待定项。保持精简，删除未采用方案的冗长讨论。

文档交给用户确认。若用户同时明确授权直接开发且需求已清楚，可按该授权继续；不要额外设置审批关卡。

用户的 UI 专属规则优先；按其规则生成示例并保存最终选定的方案与素材引用。没有 UI 请求时不主动启动可视化服务器。

## 边界

需求确认后，本技能结束。后续遵循项目规则正常开发。

不调用 Superpowers 的 writing-plans、executing-plans、TDD、worktree、审查或其他技能；不强制子代理、逐任务审批、详细实施计划。重要实现决定在正常开发中按需记录到架构文档。除非用户要求同步或已有明确授权，不因本技能自动 commit/push。
