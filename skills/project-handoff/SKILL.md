# 项目开工与收工

以仓库内文档和实际 Git 状态接续工作，不依赖旧聊天。脚本路径相对于本技能目录：`scripts/handoff.py`，使用 Python 3.10+ 和 Git，无第三方依赖。通过绝对脚本路径调用；所有命令输出 JSON。详细参数见 [命令说明](references/commands.md)。

## 初始化

用户要求为项目启用交接时，先检查已有规则、文档和 Git 状态。

- 项目尚未存在：按用户给定仓库地址克隆到明确的目录；Git 不复制未提交文件、环境变量或运行服务。
- 执行 `python <脚本> init --project <项目目录>`。已有仓库沿用当前分支；新仓库默认 main。用户指定分支时使用 `--branch`。不会自动建立远端仓库。
- 填写 `docs/product.md`、`docs/architecture.md`、`docs/status.md`，有既有权威文档时在这些入口引用它，不另写一份事实来源。初始化只创建缺失文件，并向 AGENTS.md 追加受标记管理的交接规则，不覆盖原文。
- 确认 `.handoff.json` 中的 remote/branch 是两台电脑要共同使用的分支。分支明确后不自动创建分支、worktree、PR 或发布。
- 项目首次推送若远端不存在，使用已有 GitHub 工具创建用户授权的仓库，设置 origin。公开/私有必须沿用用户的选择；未指定时不要假设公开。

## 开工／恢复

1. 运行 `python <脚本> start --project <项目目录>`。脚本要求正确分支和干净工作区，获取远端并仅允许快进；有本地未推送提交、分叉或缺少远端时报告具体状态。
2. 成功同步后重新读取 `AGENTS.md`、`docs/product.md`、`docs/architecture.md`、`docs/status.md` 及其中相关链接。旧会话中拉取也要重读，不假设指令自动刷新。
3. 对照实际提交、代码和交接核实进度；检查必要依赖、环境变量名及启动方法。不要在输出里泄漏变量值。
4. 简短说明已完成、未完成及当前先做什么。用户已要求继续时直接推进，不额外等待确认。只询问真正影响任务且无法核实的信息。

若用户只要求读取进度，不要运行会拉取/修改工作树的 start，用 `inspect` 并阅读本地文档。已有未提交工作不 reset、clean、强行 checkout 或自动 stash；先解释差异并保留工作。

## 正常开发

按项目规则直接开发。一个有意义的工作单元完成后，更新 status 的当前快照；只有需求或架构改变时才更新对应文档。保留用户确认的 UI 方案、素材位置和重要技术决定及原因。不要每改一个文件都写日志，不强制任务分解、TDD、子代理、审查或额外关卡。

## 收工／同步

用户说“收工并推送”“推送代码”等时，授权范围包含本次相关代码与交接同步。用户说“只保存本地／不要推送”时只更新文档，遵守其提交范围，不执行 finish。

1. 用 `inspect` 和 Git diff 核对实际代码、未跟踪文件、暂存内容及已有提交。区分本次工作和无关修改。
2. 基于实际执行结果写 status：当前目标、已完成、进行中、验证命令与结果（未测就写未测）、阻塞、下一步和必要决定。未完成功能可以 WIP；测试失败必须写明，不伪装完成，也不为换电脑强行合并或部署。
3. 检查必要素材、迁移和依赖锁文件是否包含。真实密钥、本地环境、依赖目录不提交。脚本有基础敏感文件检查，不能替代人工审阅。
4. 用明确文件列表运行 `finish --project <目录> --message <提交说明> --files <本次文件...>`。命令会检查远端、暂存指定路径、核对交接已更新、提交、推送并查询远端提交。只传文件，不能使用 `.` 或目录；文件名含空格要按工具要求正确传参。文件很多可用 JSON 数组文件配合 `--files-from`。
5. 读取结果：只有 `remote_verified=true` 才说该提交已推送；只有 `complete=true` 才说工作区全部同步。列明剩余本地修改。失败后检查实际状态再决定下一步；commit 已产生而 push 失败时保留它。无改动但需要重试已有提交的推送，先检查其内容，再运行不带文件参数的 finish。

回执保持简短：远端分支、已核实提交、验证结果、未完成项、下一步。不要把回执的最终提交 SHA 写回同一提交，避免产生永远推不完的新修改。

## 限制

技能随匹配的用户请求运行，不是后台监控。突然关机只保留此前已经写入磁盘／推送的内容。不同电脑的密钥、运行环境分别配置。脚本不处理语义合并，不覆盖本地改动，不强制推送；冲突处理需要结合实际差异，超出当前授权时再询问。
